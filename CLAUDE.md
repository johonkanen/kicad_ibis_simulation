# IBIS signal-integrity simulation with KiCad 10 + ngspice: instructions for Claude

Use this when asked to simulate a high-speed link (DDR/LPDDR, a fast GPIO, a clock) from IBIS models in a KiCad
project: eye diagrams, mask margins, over/undershoot, termination or trace-width decisions. Everything runs headless:
a Python script writes a KiCad schematic, `kicad-cli` turns it into a SPICE netlist (that runs KiCad's own IBIS
converter, KIBIS), libngspice simulates it, and `kicad_ibis.eye` folds the waveforms into eyes. The schematics stay
normal KiCad files the user can open and simulate in Eeschema.

The package is `kicad_ibis/` in this repo. Usually it is a git submodule of the board project
(`tools/kicad_ibis_simulation`); import it with `sys.path.insert(0, <that folder>)`.

## Rules

- **Vendor IBIS files are copyrighted.** Never commit them (most board repos are public). Keep them in a
  git-ignored `models/` folder next to the simulation and write in its README where each file comes from (URL, tool
  and command that generated it, version).
- **Do not edit the board's .kicad_pcb / .kicad_sch / .kicad_pro** for a simulation. The simulation gets its own
  folder (e.g. `sim/<link>_si/`) with its own schematic(s). Take lengths, layers and stack-up from the board, by
  reading the files or asking.
- **If a step does not work, stop and report it** (no model, parser error, a driver that does not match its V-t
  tables). Never fill a gap with guessed numbers. Say which models are stand-ins (e.g. a different vendor's part of
  the same JEDEC type when the real model is not public) and what was not modelled.
- Run the driver validation (below) before trusting any eye.

## Set-up

1. KiCad 10 AppImage, extracted once (it carries both kicad-cli and libngspice with its code models):
   `kicad-10.0.x-x86_64.AppImage --appimage-extract`, then `export KICAD_APPRUN=<dir>/squashfs-root/AppRun`.
   A system KiCad works too: set `KICAD_CLI`, `NGSPICE_LIB` (path to libngspice.so) and `KICAD_SYMBOLS`.
2. python3 with numpy, scipy (field solver only) and matplotlib. Run ngspice through `kicad_ibis.spice.ngspice()`
   (ctypes, in a fresh process per run); do not try to build ngspice or KiCad from source.
3. Models: from the silicon vendor's site, or generated by the vendor tool (FPGAs: e.g. Quartus
   `quartus_eda <proj> -c <rev> --board_signal_integrity=on --format=ibis --output_directory=ibis` writes the IBIS
   of the I/O standards and OCT settings of the actual build). Memory vendors often require an NDA; a public model of
   a same-type part (same JEDEC standard, same drive/ODT options) is an acceptable, clearly labelled stand-in.
4. Fix the files for KiCad's parser: `python3 -m kicad_ibis.ibisfix IN.ibs models/OUT.ibs` (see "KiCad 10 IBIS
   problems"). Then check every model you need parses: export a schematic with one instance of each and read the
   kicad-cli messages.

## Method

1. **Channel model** per net: IBIS driver (pin package R/L/C, C_comp) -> via (pi: C/2, L, C/2) -> TLINE segments
   (breakout neck-down, route, neck-down) -> via -> IBIS receiver / ODT model. T-topologies (DDR CA/CK to two dies)
   are TLINEs joined at the T node. Use `kicad_ibis.sch.Sch`; put all channels of one sweep point into one schematic
   (one row each), one schematic per sweep point.
2. **Line impedance and delay** from the stack-up: `python3 -m kicad_ibis.zsolve strip|micro ...` (2D field solve,
   lossless); add `--gap` for an edge-coupled pair (Zodd, Zdiff = 2 Zodd, Zeven). A symmetrically driven pair
   (DQS, CK) is simulated as single-ended legs on TLINEs of Zodd (and the odd-mode ps/mm); say so, because P/N
   skew, mode conversion and crosstalk are then not modelled. Typical vias: 0.15-0.5 nH, 0.3-0.5 pF; say they are estimates unless solved.
3. **Stimulus:** `PRBSDRIVER` with `f0=<bit rate> n=<bits>` (f0 is the BIT rate, not the clock), ~150 bits, plus
   `.tran 1p <bits*UI + 2 ns>` and `.options method=gear maxord=2 reltol=1e-4`. Corners: append
   ` vcc=MIN rpin=MIN lpin=MIN cpin=MIN` (or MAX) to the driver and receiver params, upper case.
4. **Export and run:** `spice.export(sch_path)` (serially: KIBIS shares one cache folder), then
   `spice.ngspice(cir, nodes, dat)` (parallel is fine, e.g. ProcessPoolExecutor). Probe the receiver pin (net name)
   and die (`x<ref>.die0`, ref lower case).
5. **Eyes:** `eye.analyse(t, v_driver_die, v_rx, ui, mask)`; show one with
   `python3 -m kicad_ibis.show_eye work/x.dat --drv xu1.die0 --rx xu2.die0 --rate 1600 --mask rect:140m:0.22`
   (interactive window; `--png` to save). Quick single link: `python3 -m kicad_ibis.p2p ...`.
6. **Validate the converted drivers** first: each driver as `RECTDRIVER` (`ton=3n toff=3n td=1n n=1`) into 50 ohm to
   GND, package zeroed (`spice.strip_package` on the copied cache file), compared with the model's
   `[Rising/Falling Waveform]` table for V_fixture = 0 (`ibisfix.waveform`, `ibisfix.t2080`): levels within a few mV,
   20-80 % edges within a few ps. Report any model that is off.
7. **Judge** each receiver against its Rx mask (JEDEC for DRAM inputs; vendor data for FPGA inputs, or a clearly
   labelled proxy) and the abs-max over/undershoot of both data sheets. Report eye height/width, mask margins
   (V and t), Vmax/Vmin, worst of pin and die, typ and min/max corners, and every assumption.
8. **Prove the analysis can fail** before reporting "everything passes": run a deliberately bad case (very high Z,
   long line, missing termination) and check that the margins go negative where expected and that the eye plot
   agrees (open eye = no fail, whatever the numbers say).

## KiCad 10 IBIS problems (10.0.7) and the workarounds

| problem | symptom | workaround |
|---|---|---|
| `[Pin]` column names matched case sensitively | `R_Pin L_Pin C_Pin` ignored or parse error | `ibisfix.fix_pin_header` |
| `[R Series]` / `[Series Pin Mapping]` rejected | whole file fails | `ibisfix.drop_series` (drops the series models) |
| `[Define Package Model]` ignored | no package when `[Package]` is zero | `ibisfix.package_to_pins` (self R/L/C only) |
| Ku/Kd PWL sources with ~1e5 points and solver spikes | ngspice never finishes; spikes on edges | `spice.clean_cache` (on by default in `export`) |
| corner keywords are case sensitive | `min`/`max` silently give typ | use `MIN`/`MAX` |
| C_comp has no corner | always typ | note it |
| PRBS `f0` | is the bit rate | `f0 = 1/UI` |
| headless CLI | only the parser's last message is printed | export one model at a time when debugging |
| KIBIS warning "Bitrate could be too high for rising / falling edges" | printed for most fast links | harmless; `export` filters it |
| AMI (`[Algorithmic Model]`) | not supported | analog only: `ibisfix.extract_models` drops it |

## Eye analysis pitfalls (handled in `kicad_ibis.eye`; keep them in mind when changing it)

- **Bit labels must come from the stimulus, not from a waveform.** KiCad's PRBSDRIVER sends a fixed PRBS7
  (x^7+x^6+1, `eye.kibis_prbs7`); only its whole-bit alignment is fitted to the driver die waveform. Sampling the
  driver die directly flips isolated bits on mismatched lines (the reflection comes back to the die) and gives
  closed "eyes" that are not real.
- The receiver delay is the cross-correlation peak, refined by the whole-UI shift that opens the eye most.
- Leave out the start-up bits (`skip`) and the tail after the stimulus (`tail`).
- A red (1) trace inside the blue (0) band in `show_eye` means a wrong label or a really closed eye: look at the
  raw waveforms (driver die and receiver, with the bit grid) before reporting a failure.

## Output

Per simulation folder: the generator script, the run script, `README.md` (what is modelled, models and where they
come from, how to rerun, results, what was not modelled), `results/` with CSVs, a markdown table and eye PNGs, and
one baseline schematic committed so the user can open it in Eeschema. Git-ignore `models/`, `work/`,
`__pycache__/`, `*.kicad_prl`.
